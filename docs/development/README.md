# MediPencil 개발명세 — PoC 이후 재확정 예정

**현재 Codex 시작점은 [PoC 제작·사용 검증 계획](../poc/README.md)과 [AGENTS.md](../../AGENTS.md)다.**

2026-10-03 사용자 결정 D-11: 출국 전 온라인 지원팀과 작동 PoC를 검토하고, 실증·피드백을 받은 뒤 상세명세를 다시 작성한다. 이전의 ‘명세 전체 확정 → C 작업 전체 구현’ 순서로 진행하지 않는다.

## 3. 지금 할 일

독립 합성자료와 직접 입력으로 서로 다른 브라우저의 가족·직원 세션을 실제 서버·DB에 연결한다. 질문 접수, 기록 수정·승인, 발행, 공개 범위에 맞는 답·근거 조회를 먼저 작동시킨다. 이후 확인된 엔진을 붙이고 온라인 지원팀의 실제 의견을 받는다.

실행 가능한 화면을 만드는 대신 문서를 계속 확장하지 않는다. 필요한 최소 테이블·API는 구현자가 선택하고 간단한 이유를 기록한다. 승인 전 노출 금지, 계획/완료 구분, 근거 충실, 동의 후보/확정 구분, 서버 권한, 정정·철회·삭제 결과의 정직한 표시를 약화하지 않는다.

기본 기술 후보는 FastAPI/Python + SQLite + React/TypeScript/Vite다. 실제 엔진·공유 서버·배포 권한은 확인해야 한다. 엔진 미연결은 그 시험만 BLOCKED로 남기고 직접 입력 경로와 사용 검토를 계속할 수 있다. 공유 서버가 없으면 로컬 검증 완료와 배포 대기를 구분한다.

## 4. 명세를 다시 확정하는 시점

PoC 구현·시험·지원팀 검토 → 문제와 FB-ID 기록 → 수정·재시험 → 유지/변경/보류/제외 요구 제안 → 사용자 승인 → 다음 버전 상세명세 작성 순서다.

후속 명세에는 실제 채택한 화면 흐름·DB·API·AI 연결·배포·권한·시험 조건만 확정하고, 피드백과 반영 위치를 연결한다. 자동 테스트만 통과한 상태나 지원팀의 의견이 아직 없는 상태에서 ‘실증 완료’로 보고하지 않는다.

이번 변경에서는 PoC 실행계획과 Codex 지침만 전환했다. 앱 코드 구현·실행·서버 배포·사람 피드백 수집·주최 측 확인은 완료하지 않았다. 실제 작업 기록은 작업 시작 후 `docs/poc/validation-log.md`에 남긴다.

## 5. 대회 사용과 데이터 경계

PoC는 대회 사전제작 규정의 예외라는 뜻이 아니다. 기존 지침의 행사 중 제작 경계, 주최 측 확인·출발점 신고·제작 이력 보존은 그대로 적용한다. 내부 검토용 구현의 대회 반입·재사용·출전 자격 영향은 docs/poc/README.md §8의 확인 과제로 남긴다. 별도 브랜치나 출품 제외 표기만으로 적격성이 확보됐다고 주장하지 않는다.

PoC에는 Veil.AI에서 유래하지 않은 독립 합성자료만 쓴다. 실제 환자·입주자 정보·실제 돌봄 음성·Veil 원본/파생물·비공개 엔진·키·검토자 개인정보는 공개 저장소나 개발 에이전트 입력에 넣지 않는다. 실제 모델·외부 처리·배포 권한을 임의로 승인하지 않는다.
