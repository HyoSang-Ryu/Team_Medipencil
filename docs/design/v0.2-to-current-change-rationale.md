## 2. 원안에서 그대로 유지한 핵심

가족의 질문을 기존 대화에 넣고, 그 대화에서 사람이 확인한 답을 기록으로 남겨 가족에게 다시 전달하는 다섯 단계 루프를 유지했습니다. AI가 가족의 의료 질문에 독자적으로 답하지 않고, 기존 기록을 재사용해 별도 응대를 줄이려는 목적도 같습니다. [S1 §3.1·8; S3 §3.1·8.3]

출처 연결, 근거 없으면 “기록 없음”, 사람의 확인, 수신자별 동의, 모의 EMR, 실제 환자·음성 배제는 v0.2에 이미 있었습니다. 후속 설계의 기여는 이 원칙을 처음 만든 것이 아니라 상태·버전·서버 검사·검증 사례로 구체화한 데 있습니다. [S1 §3.3·5.5·6.1·7·8]

판정 구분: [공식 대조] 공식 문서와의 차이 확인 / [내부 선택] 범위·구현 판단 / [정합성 보정] 원문·목업·상태의 불일치 수정 / [사용자 결정] 진행 순서 변경. 실제 효과·현장 적합성이 검증됐다는 뜻은 아닙니다.

### 원안의 잘못과 공식 문서 변경을 구분해야 합니다

v0.2에는 “LUVN 8질문 그대로”라고 쓰여 있지만, 이번에 확인한 공식 2.2 문서에서는 8칸을 의무화한 근거를 찾지 못했습니다. 따라서 “주최 측이 병동·8칸을 거주시설·6칸으로 변경했다”가 아니라, “우리 해석과 구성을 공식 상세 설명에 맞게 조정했다”가 정확합니다. 과거 공식 상세문서의 동일 조건 비교로 변경 시점까지 확정한 것은 아닙니다. [S1 §2·3.3; S5]

### R2의 “오른쪽·며칠 동안” 수정은 중간 버전의 오류 보정입니다

이 문구는 거주시설로 바꾼 v0.3/v1.0의 목업·예시에서 전사에 없는 세부정보가 추가된 문제였습니다. v1.1은 이를 제거하고 목업 이미지와 JSON을 함께 맞췄습니다. v0.2의 원래 시나리오는 계단·퇴원이므로, 이 보정을 v0.2를 버린 이유로 설명해서는 안 됩니다. [S1 §4.1; S2 §4.1·6.2; S3 §5.3~5.5·6.4.1]

위 처리 방식은 팀의 정합성·안전 설계입니다. 공식 2.2의 원자료 충실·동의 원칙에 대응하지만, 구체적인 상태명·DB 구조·클릭 수를 주최 측이 요구한 것은 아닙니다. [S5 8쪽]

### 데이터 규정과 팀의 보수적 운영안은 다릅니다

공식 규정은 상용 AI 도구 사용을 허용하면서 Veil 자료의 제3자 제공·공개·재배포를 제한합니다. 외부 API에 Veil 내용을 보내는 예외나 파생물별 상세 처리는 명확하지 않습니다. 따라서 “외부 AI는 금지”가 아니라 “해당 자료의 전송·보관 범위는 확인하고, 그 전에는 차단”으로 설계한 것입니다. [S6 §8~9; S3 §7.2]

### 효과를 약하게 만든 것이 아니라, 입증 조건을 정했습니다

“가족의 편익을 높이되 직원 부담을 줄인다”는 원안의 목표는 유지합니다. 다만 확인 단계가 늘어난 현재 구조가 실제로 더 빠르다는 증거는 아직 없습니다. PoC에서는 생성 시간뿐 아니라 검토·수정·발행 시간을 함께 재야 하며, 전화가 질문 큐로 옮겨간 것만으로 절감이라 계산하지 않습니다. [S3 §12; S4 §6]

| ⑱ 언어 | 원안 표는 FI/EN 필수, SV·쉬운 말은 선택 → 쉬운 FI 우선, 전체 SV/EN 선택 | 과제의 쉬운 표현 요구에 맞추고 전체 번역 부담을 줄임. 현재 한국 온라인 검토에는 한국어 설명을 먼저 제공하며 FI 성능·검수는 별도. 영어 발표 자체가 금지된 것은 아님. [S1 §5.5·9.2; S3 §5·9.3; S4 §3; S5·S6 §19] |
| ⑲ 엔진과 연동 | 닥터펜슬 중심 SOAP·클립보드 모의 EMR → 기존 음성 기술을 연결부로 분리, 모의 기록·승인·발행 중심 | 실제 엔진 계약·권리·FI 성능을 확인하며 나머지 흐름을 시험하려는 조치. 원안도 실 EMR 쓰기는 제외했고 모의 EMR을 명시. 목업 “Save to EMR”을 실제 운영 연동으로 읽으면 안 됨. [S1 §5.5·6.1; S3 §6.1; S4 §3~4] |
| ⑳ 구현 상세 | 상위 아키텍처 후보 → 18테이블·40API 상세명세 → PoC의 최소 필요 구조로 재조정 | Codex의 구현 해석 차이를 줄이려 구체화했으나, 검증 전 모두 고정하는 것은 사용자 목적보다 앞선 설계였음. 숫자는 공식 요구가 아니며 지금 전부 구현할 의무도 없음. [S4 §1·3] |
| ㉑ 평가·파일럿 | 문서의 4개 심사축·병동 20명/4주 → 공식 5개 축·거주시설 20명/4주 제안 | 심사축은 공식 내용과 맞추고 파일럿 무대는 사용처 변경에 따라 조정. 규모는 제안 그대로이며 임상 성과·도입 확정 아님. [S1 §10·12; S3 §11~14; S6 §11] |

### 변경으로 약해질 수 있는 원안의 강점도 있습니다 — 비교 판단

원안은 “음성으로 기존 회진 기록을 자동화해 가족 답변을 재사용한다”는 메시지가 선명했습니다. 센서·권한·상태·감사 항목을 지나치게 전면에 놓으면 음성 엔진의 가치와 업무 절감 메시지가 흐려질 수 있습니다. 직접 입력만으로 검토를 마치면 음성 자동화의 가치도 검증하지 못합니다. [S1 §1.2·3.3; S4 §2·6에 근거한 비교 판단]

따라서 정확성과 공개 통제는 유지하되, 실제 사용 화면에서 확인 부담이 얼마나 생기는지와 음성 연결이 그 부담을 상쇄하는지를 검증해야 합니다. 모든 보강이 필연적으로 더 좋은 제품을 만든다고 단정할 단계는 아닙니다.

## 7. 개발 순서의 변경: v0.2 → v1.1 → D-11

| 시점 | 계획 | 왜 변경했는가 |
| --- | --- | --- |
| v0.2 | 10/3 음성·모의 EMR, 10/8 질문부터 카드까지 사전 완성 | 원래는 충분히 작동시킨 데모를 가져가 현장에서 데이터·대본을 맞추는 준비 계획. [S1 §9.2~9.3] |
| v1.1 및 상세명세 | 기존 범용 자산과 과제 전용 구현을 나누고, 대회용 전용 구현은 행사 중 | 공식 §7의 사전 준비와 과제 해결책 제작 경계를 반영. 상세문서도 허용 수준을 주최 측에 확인할 수 있도록 미결 과제 유지. [S3 §9·15; S6 §7] |
| 최신 D-11 | 출국 전 PoC → 온라인 지원팀 사용 검증 → 수정·재시험 → 명세 재작성 | 사용자가 “같이 써보며 소통하고 피드백을 받은 뒤 명세를 만든다”는 목적을 명확히 하여 순서를 변경. 규정 완화나 현장 검증 결과에 따른 변경은 아님. [S4 §1·4·7·8] |

> D-11이 바꾼 것은 내부 작업의 우선순위입니다. 대회 사전제작·반입·재사용 허용은 여전히 미확정입니다. “내부 PoC”, “합성자료”, “별도 브랜치”라는 명칭만으로 규정의 예외가 생기지 않습니다.

현행 §7의 행사 중 제작 원칙은 이번 확인에서도 유지됩니다. 같은 과제의 작동 PoC를 사전에 제작하는 범위, 출품·재사용, 등록 팀원 외 지원인력의 기여는 주최 측 확인이 필요한 별도 사항입니다. 이 비교 문서는 허용 회신을 받았거나 제작을 완료했다는 증빙이 아닙니다. [S6 §5·7; S4 §8]

### 현재 무엇을 유지하고 무엇을 다시 결정하는가

| 유지할 기준 | PoC 뒤 다시 결정할 것 |
| --- | --- |
| 가족 질문을 기존 돌봄 대화·기록과 잇는 루프 | 실제 돌봄 담당자·확인 주기·질문 처리 방식 |
| 계획/완료, 승인 전/후, 공개 허용/비허용의 구분 | 확인·발행 화면 수, 반복 작업을 줄일 UI 구성 |
| 근거·원자료 의미·삭제 결과를 사실대로 표시 | 실제 엔진·필요 DB/API·성능·배포 방식 |
| 실제 피드백과 미검증 항목을 구별 | 2.1·전체 다국어 등 추가 범위의 우선순위 |

PoC 완료는 화면이나 자동 테스트만으로 판단하지 않습니다. 실제 지원팀 피드백과 중요 결함의 재시험까지 확인하고, 이후 변경 요구를 사용자에게 제시합니다. 시설 실무자 검증·임상 효과·주최 측 허가는 각각 별도입니다. [S4 §5~8]

## 8. 결론과 출처

> 변경 취지는 “회진 루프를 버리고 다른 앱을 만든다”가 아닙니다. 가족 질문이 기존 업무에서 확인된 기록과 답으로 돌아오는 구조는 유지하면서, 과제 대상에 맞춰 현장을 옮기고 원자료·권한·상태를 보강했습니다. 이후 과도한 사전 확정을 피하기 위해 PoC 검증과 피드백을 상세명세보다 앞에 두었습니다.

### 변경 사유를 설명할 때 피해야 할 네 가지

① “주최 측이 8칸을 6칸으로 바꿨다” — 칸 수는 우리 설계 선택입니다.  
② “원안에는 근거·승인·동의가 없었다” — 원안에 이미 있었습니다.  
③ “센서 앱·텍스트 문의 앱으로 바꿨다” — 센서와 직접 입력은 원래 루프를 보조하며 음성의 실제 효용은 별도로 검증해야 합니다.  
④ “PoC니까 미리 만들어도 대회에서 문제없다” — 내부 계획과 참가 규정상 허용은 별개입니다.
