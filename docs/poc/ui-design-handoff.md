# MediPencil PoC — UI/UX 디자인 및 적용 안내

작성: 2026-10-04 · 용도: 디자이너/구현자에게 전달하는 현재 앱의 디자인 작업 입력물

**목표:** 온라인 지원팀이 가족 질문 → 직원 확인 → 기록 검토·승인 → 발행 → 가족 답변·근거 열람을 이해하고 시험할 수 있도록 화면을 개선한다. 아래는 현재 코드와 적용 경계이며, 피드백 이후 확정할 다음 제품 상세명세가 아니다. 새 디자인의 색상·레이아웃·컴포넌트는 아직 선정하지 않았다.

## 1. 디자인 작업 범위

- 화면 1~5의 가족·직원 흐름과 사용자 요청으로 추가한 PoC 팀 코멘트 메뉴.
- 한국어 PoC 안내 + 기존 FI 화면, 영어 UI 전환 지원. 팀 코멘트 메뉴는 한국어/영어.
- 데스크톱에서 직원 검토, 모바일에서 가족 열람과 팀 코멘트가 가능하도록 설계.
- 사용자 입력 원문은 번역하지 않는다. UI 언어와 발행 콘텐츠 언어는 별개다.
- 화면 6 사전문진, 회원가입, 예약, 알림, 채팅, 파일 첨부, 실시간 협업은 이번 디자인에 추가하지 않는다.

## 2. 현재 실행 및 기술 구조

React + TypeScript + Vite, React Router, TanStack Query, 기본 CSS. 서버는 FastAPI, 저장소는 SQLite다. 디자인 적용을 위해 UI 프레임워크를 새로 설치할 필요는 없다.

```bash
# 저장소 루트, 프로젝트가 요구하는 Node 22 환경에서
npm --prefix apps/web run build
.venv/bin/python tools/dev/run_demo.py --poc --port 8767
```

`http://127.0.0.1:8767`에서 검토한다. 실행 중인 회차가 있으면 새 DB를 만들지 말고 기존 서버를 이용한다. 재시작이 필요한 경우 출력된 기존 경로를 `--data-root`로 전달한다. DB를 reset하지 않는다.

상단에서 **Liisa**(가족 A), **Mikko**(가족 B), **Koskinen**(직원)을 선택한다. 두 역할을 연결해 시험할 때는 쿠키가 분리된 브라우저/프로필을 쓴다. 상단 **Interface / 화면 언어 → English**는 UI만 변경한다. 페이지 새로고침 후 UI 언어와 역할을 다시 선택한다.

공유 배포는 아직 미승인이다. 이 주소는 실행 컴퓨터의 로컬 주소이며, 팀원의 다른 컴퓨터 접속주소가 아니다.

| 화면/역할 | 경로 | 현재 코드 | 디자인할 핵심 요소 |

| 2 직원 질문 큐 | `/staff/queue` | `App.tsx`의 Questions | 질문 목록, 확인 예정 시각, 확인 예약, 미답변 유지 |
| 3 기록·검토 | `/staff/residents/aino/capture` | `Capture.tsx`, `Audio.tsx` | 질문 연결, 직접 입력/로컬 처리 구분, 원문/화자/유형/공개 분류, 수정·저장·승인, 실패 복구 |
| 4 발행 | 위 capture 경로의 하단 | `Publication.tsx` | 수신자 선택, 미리보기, 문장별 검토, 발행 버튼, 발행 결과 |

코멘트 메뉴는 **PoC 모드 + 직원 역할**에서만 보인다. 가족 역할에는 메뉴도 응답 내용도 공개하지 않는다. `Koskinen`은 데모 역할이며, 팀원 별칭은 인증된 개인 계정이 아니다. 해당 화면을 환자용 화면6으로 취급하지 않는다.

## 4. 반드시 그릴 상태

| 영역 | 필요한 변형 |
| --- | --- |
| 공통 | 사용자 미선택, 가족, 직원, 영어, 긴 한국어/FI 문구, 네트워크 끊김, 세션 만료 |
| 가족 카드 | 미공유 / 기록 없음 / 검토 대기 / 발행된 진술·관찰·계획 / 발행 언어 미지원 |
| 근거 | 열림/닫힘, 접근 철회·근거 이용 불가, 긴 발췌 |
| 질문 | 빈 목록, 접수, 확인 예약, 미답변, 발행 후 답변됨, 저장 실패와 입력 유지 |
| 기록 | 빈 입력, 생성 중, 초안, 수정 중, 수정 저장 전 승인 불가, 검토 체크 전 승인 불가, 승인됨, 정정 |
| 발행 | 수신자 미리보기 전, 미리보기, 검토 전 발행 불가, 발행 중, 성공, 권한/버전 충돌 및 재검토 |
| 동의 | 후보만 있음, 확정됨, 일부 범위 철회, 근거/확인 부족 |
| 코멘트 | 비어 있음, 작성 중, 저장 중, 저장 성공, 저장 실패 시 입력 보존, 필터 결과 없음, 목록 조회 실패 |

상태는 색상만으로 전달하지 말고 텍스트를 같이 둔다. 비공개·정보 없음·로딩을 같은 회색 카드 하나로 합치지 않는다. 코멘트의 저장 성공과 목록 조회 성공은 다른 요청이므로 구분한다.

## 5. 디자인 전달 형식

다음 내용을 디자인 파일/이미지와 함께 전달하면 구현에 바로 사용할 수 있다. 빈 값은 실제 디자인 결정 후 채운다.

```text
디자인 이름 / 버전 / 날짜:
디자인 파일 또는 이미지 경로:
대상 화면과 상태:
변경 목적과 관련 실제 코멘트 ID(있으면):
기준 화면 폭: desktop 1280 / mobile 390 / 최소 검토 360
색상 토큰:
  page / surface / text / muted / border / primary / focus / error / success
타이포그래피:
  font / h1 / h2 / body / caption / weight / line-height
간격·형태:
  spacing scale / content max-width / card padding / gap / radius / border / shadow
컴포넌트:
  button primary-secondary-disabled-loading / input / select / textarea
  tabs / status badge / card / notice / error / evidence panel / comment item
반응형 규칙:
  줄바꿈 / 카드 열 수 / 직원 원문-검토 영역 배치 / 내비게이션 방식
인터랙션:
  focus / hover / pressed / loading / empty / error / success
문구 변경:
  기존 키 / 제안 문구 / 한국어·영어·FI 검수 상태
에셋:
  파일명 / 용도 / 사용권 / 대체 텍스트
승인된 시각 결정 / 아직 검토할 결정:
```

실제 환자 자료·실제 팀원 이름·비공개 코멘트 원문을 디자인 파일이나 공개 저장소에 복사하지 않는다. 레이아웃 예문은 독립 합성 텍스트로 쓴다.

## 6. 코드에 디자인을 적용하는 위치와 순서

1. 위 화면/상태와 디자인 산출물을 매핑한다. 변경하려는 파일과 디자인 의도를 정리한다.
2. `apps/web/src/style.css`의 현재 색상·간격·라운딩을 CSS custom properties로 묶고 승인된 디자인 값을 적용한다. 현재 전역 선택자는 모든 화면에 영향을 주므로 특정 화면 변형에는 의미 있는 클래스명을 추가한다.
3. `App.tsx` 공통 헤더/내비게이션부터 적용하고, `Board` → 질문 큐 → `Capture`/`Publication` → `Consent` → `ReviewComments` 순서로 적용한다. 필요하면 표현 컴포넌트만 추출한다.
4. 영어 UI 문구는 `english.json`, UI 언어 상태는 `UiLanguage.tsx`에서 다룬다. 입력 데이터에 번역 함수를 적용하지 않는다. 변경한 기본 라벨에 대응하는 영어 항목을 함께 갱신한다.
5. 상태·권한·요청을 담당하는 `api.ts`, `jobs.ts`, `segmentEdits.ts` 및 서버 계약은 시각 변경을 위해 재작성하지 않는다. 디자인상 동작 변경이 필요하면 별도 의사결정으로 분리한다.
6. 아래 검증을 수행하고 `docs/poc/validation-log.md`에 파일·명령·실패/수정·재시험·커밋을 남긴다. 실제 코멘트를 반영했다면 내부 코멘트 ID와 공개 가능한 익명 요약만 연결한다.

현재 스타일의 참고값: page `#f2f5ef`, surface `#fff`, text `#163e39`, primary `#236459`, main max-width `1120px`, section radius `16px`, button radius `8px`. **기존 구현값이며 새 디자인의 확정값은 아니다.**

## 7. 디자인으로 바꾸면 안 되는 동작

- **기록 승인 ≠ 가족 발행.** 두 검토·동작·결과를 하나의 버튼이나 성공 표시로 합치지 않는다.
- **계획 ≠ 완료.** 계획에는 완료 체크 아이콘이나 완료 문구를 붙이지 않는다.
- **동의 후보 ≠ 공개 권한.** 후보 생성 직후 공개된 것처럼 보여주지 않는다.
- 화면에서 정보를 감추는 것은 서버 권한 검사의 대체가 아니다. 숨긴 원문을 미리 받아 CSS로 감추지 않는다.
- 정정·철회·오프라인 시 옛 내용이 다시 나타나게 캐시/fallback을 만들지 않는다.
- 직접 입력, 실제 STT/LLM, 모의/재생 결과를 구별한다. 현재 `--poc`는 AI 미사용이다.
- 언어 변경으로 사용자·공개 범위를 바꾸거나 작성 중 입력을 없애지 않는다.
- 저장 실패에서 입력을 유지하고 재시도 중복을 막는 idempotency key를 보존한다.
- 코멘트는 돌봄 기록·발행·동의 근거로 연결하지 않는다. HTML/Markdown 실행 없이 텍스트로 표시한다.
- 별칭·데모 역할을 실제 팀원 인증으로 표현하지 않는다. 디자인 적용이 공유 배포 승인은 아니다.

## 8. 검증 체크리스트

```bash
npm --prefix apps/web run typecheck
npm --prefix apps/web run test:run
npm --prefix apps/web run test:e2e
npm --prefix apps/web run build
# 서버·권한·저장 계약도 변경했다면
.venv/bin/python -m pytest apps/api/tests -q
```

- 1280px/390px/360px에서 가로 넘침, 긴 문구, 줄바꿈, 모바일 키보드·포커스를 확인한다.
- 레이블 연결, 키보드 이동, 보이는 포커스, 오류/성공 안내, 명도 대비를 확인한다. 자동 통과를 접근성 인증으로 표현하지 않는다.
- FI/한국어 안내와 영어 UI 양쪽에서 메뉴와 버튼을 확인한다. 시각 변경 때문에 접근성 이름 기반 테스트를 무작정 제거하지 않는다.
- 서로 다른 브라우저 세션에서 돌봄 루프·공개 제한을 재검증한다.
- 코멘트 저장 → 다른 직원 세션 새로고침 → 동일 내용 확인 → 필터 → 재접속을 확인한다. 가족의 코멘트 API 접근은 차단되어야 한다.
- 실패 후 재시도, 승인 전 공개 차단, 수정 저장 전 승인 차단, 철회 후 근거 차단을 유지한다.
- 캡처와 실제 실행 결과를 남기되 자동 시험 자료를 사람 피드백으로 등록하지 않는다.

```text
기존 실제 서버·DB 흐름과 승인/발행/권한/정정/언어 경계를 보존하라.
새 제품 기능이나 전체 상세명세를 추가하지 마라.
한국어 안내·영어 UI와 원문 데이터의 구분을 유지하라.

미확정된 디자인 선택은 가정을 명시하되, 서버 계약 변경은 별도 결정으로 다뤄라.
```
