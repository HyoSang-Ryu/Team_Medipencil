# 모바일 중심 음성 차팅·보호자 안내 설계 정리

작성: 2026-10-13. 상태: 대화에서 도출한 검토안. 최종 제품 명세나 구현 완료 선언이 아니다.

## 목표
간호사가 한 번 기록한 근거를 직원용 차팅과 보호자 안내에 함께 활용한다. 기존 EMR과 신규 음성 기록을 시간순으로 연결해 변화 설명에 활용한다. 여기서 환자 상태 '학습'은 우선 확인된 이력 축적과 조회·비교를 뜻하며 모델 파라미터 재학습을 포함하지 않는다.

## 현재 구현과 추가 범위
기존 합성 EMR 가져오기, 음성 WAV 업로드·로컬 STT 어댑터, 초안 검토·승인·발행, 공유 범위, 가족확인사항, 제한된 일상기록 정기 전달, 기록 건수 그래프를 재사용한다. 실제 병원 EMR 양방향 연동, 모바일 마이크 녹음, 네 영역 구조화 차팅, 문맥에 따른 누락 질문, 하나의 검토로 직원 기록·가족 안내 확정, 실제 수치 추이는 추가 개발이다. 실제 AI 실행은 환경별 실행 증빙으로 구분한다.

## 모바일 공통
- 모바일 단일 열을 기본으로 하고 PC에서는 목록·원문·검토 영역을 나란히 확장한다.
- 로그인은 큰 배경 이미지보다 역할 선택과 로그인 동작을 우선한다.
- 하단 고정 메뉴, 환자 사진·이름·선택 대상을 일관되게 표시한다. 두 부모를 보는 경우에도 환자별 권한·세션·작성 중 내용을 분리한다.
- 주요 조작은 큰 터치 영역(목표 44~48px 이상), 글자 확대·색 이외의 상태 문구·스크린리더 라벨을 제공한다.
- 자동 임시저장, 서버 저장 상태, 연결 실패·재시도, 중복 저장 방지, 환자 전환 확인이 필요하다. 로컬 민감정보 저장·보존 방식은 실제 자료 적용 전에 별도로 정한다.
- 동적으로 바뀌는 것은 질문이며 메뉴·버튼 위치와 단계는 유지한다.

## 직원
첫 화면: 담당 환자, 이어 쓸 기록, 확인할 업무, 큰 '돌봄 기록하기' 버튼.
하단 메뉴 제안: 홈 / 환자 / 기록 / 더보기.
흐름: 환자·관찰시각·근무 회차 선택 → 녹음 또는 직접 입력 → STT 원문 확인 → ①~④ 분류 → 누락 보완 → 직원 기록·가족 안내 동시 확인 → 저장.
녹음은 버튼 시작/종료를 우선한다. 경과시간·일시정지·취소·녹음 여부를 명시하고 음성 호출은 후속 단계로 둔다. 주변 대화 상시 수집은 기본 동작이 아니다.

## 차팅 네 영역
|영역|항목|
|---|---|
|① 일상생활·활동|식사별 섭취량·보조 정도, 수분량과 단위, 위생 보조·피부 관찰, 소변·대변·변비 관련 관찰·기저귀 교체, 이동 거리·보조기구·도움·낙상 관련 관찰|
|② 건강 상태·측정|측정한 혈압·맥박·체온·혈당과 단위/시각, 통증 위치·척도·점수·처치 후 반응|
|③ 투약·약물 처치|약물·시각·실제 복용/거부/미확인, 필요시 약물 투여 이유·결과와 후속 확인|
|④ 심리·사회|기분, 불안·초조, 대화·의사 표현, 활동 참여·교류 (세부 항목은 현장 검토 필요)|

이는 시설 기록표의 검토 후보이며 모든 환자에게 모든 측정/질문을 매번 필수로 요구한다는 뜻이 아니다. 필수 여부는 시설 양식·환자별 돌봄 계획·이번 회차 업무에 따라 설정한다.

## 분류·누락 질문 로직
1. 입력을 환자·관찰시각·화자·출처에 묶고 원문을 보존한다.
2. 문장에서 영역/필드 후보와 근거 구간을 만든다. 값·단위·부정·시제·관찰/진술/계획을 분리하며 입력에 없는 수치와 정상 판단을 만들지 않는다.
3. '항목 언급'과 '필수 세부 정보 충족'을 구분한다. 식사했다는 말만으로 섭취량/보조 여부를 완료하지 않는다.
4. 상태는 검토 필요 / 확인 완료 / 추가 질문 / 미확인 / 해당 없음 / 후속 확인 예정으로 구분한다. 해당 없음과 후속 확인은 직원이 명시적으로 선택하며 이유·확인 시점을 남긴다.
5. 차팅 마무리에서 조건에 맞는 누락/충돌/단위 불명/후속 질문만 표시한다. 질문 하나씩 큰 선택 버튼·숫자 키패드·음성/텍스트 답변을 제공한다.
6. 추가 답변은 이전 근거를 덮어쓰지 않고 수정 이력과 연결한다. 이미 답한 질문은 반복하지 않고, 새 질문이 생기면 건수를 안내한다.
7. 과거 기록은 비교 근거이며 오늘 수행한 것으로 복사하지 않는다. 병원 처방은 복용 확인이 아니고 계획은 실행이 아니다.
8. 미해결 항목을 숨기거나 전부 완료로 표시하지 않는다. 직원 확인 후 확정하며 공개 범위와 현재 근거를 서버에서 검사한다.

## 한 번 확인·두 번 활용
동일한 근거로 직원용 상세 기록과 보호자용 쉬운 안내 초안을 함께 만든다. 확인된 내용의 단순 재사용에는 중복 확인을 줄이되 새로운 해석·상충 내용·수정으로 의미가 바뀐 출력은 확인 대상으로 남긴다. 승인/동의/발행을 AI가 확정하지 않는다. EMR 전송 실패를 저장 완료로 표시하지 않으며 재시도 시 중복을 방지한다. PoC는 모의 EMR 저장함부터 검증하고 실제 연동은 별도 접속/인터페이스 확인 후 진행한다.

## 보호자
하단 메뉴 제안: 오늘 / 변화 / 가족확인사항 / 더보기.
첫 화면 순서: 부모 사진·이름·최근 소식 시각 → 오늘 안부 → 이전과 달라진 점 → 확인할 일정 → 작은 추이 그래프·상세보기.
현재 기록 건수는 건강 점수가 아니다. 구조화 값이 확보되면 식사량·수분량·이동 거리 등 동일 단위와 비교 가능한 관찰값의 추이를 제공한다. 누락을 0으로 채우거나 서로 다른 측정값을 임의 점수로 합치지 않는다. 원문·근거·상세 표는 펼쳐 보기로 제공한다.
매일 핀란드 18시 새 내용만 전달하는 기존 방향을 유지하되, 새 차팅 자료를 자동 전달 대상으로 포함하는 정책은 구현 시 명확히 정의한다. 기존 자동 전달 예외를 일반 AI 초안에 자동 확대하지 않는다. 외부 푸시/문자·이메일은 현재 앱 내 전달과 구분한다.

## 구현 순서와 검증
1. 차팅 스키마·필수 조건·원문 근거·누락 질문 엔진 (직접 입력 먼저).
2. 직원 모바일 기록·보완·임시저장/재개와 기존 검토 흐름 연결.
3. 모바일 녹음·로컬 STT/LLM 연결. 엔진은 교체 가능한 어댑터로 유지.
4. 직원 기록·가족 안내 병렬 초안과 한 번의 확인 흐름.
5. 보호자 모바일 첫 화면·상태값 추이·정기 전달 연결.
6. 실제 EMR 연결·음성 호출·외부 알림은 후속 단계.
검증: 다른 환자 혼입, 미입력/부정/예정의 오분류, 단위 누락, 필요시 투약 후속 질문, 저장 중 이탈/오프라인, 권한 철회, 중복 전송, 근거 정정, 새 해석의 미검토 발행을 확인한다. 실제 엔진 시험·합성 시연·미검증·현장 피드백을 구분한다. 관련 기존 추적: T-01/T-02/T-03/T-05/T-10; 새 요구의 세부 T-ID는 구현 시 연결한다.

## 데이터 경계
독립 합성 PoC와 외부 제공 데이터는 출처를 분리한다. 제공 자료 원문·개별 식별자·분석 산출물은 이 문서나 공개 저장소에 포함하지 않는다. 자료 분석은 별도 로컬 폴더에서 수행하며, 이번 정리는 코드 변경·배포·모델 학습·대회 반입 승인으로 간주하지 않는다.
