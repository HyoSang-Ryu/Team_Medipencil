# 가족확인사항 · 합성 EMR 일정 컨셉

2026-10-08 사용자 요청에 따른 PoC 확장. 후속 지시: 실제 EMR 연동이 아닌 컨셉과 독립 합성 데이터만 사용한다.

## 작동 흐름

1. Koskinen으로 로그인하여 **가족확인사항 → 합성 EMR 일정 가져오기**에서 예시를 채운다. 진료·검사·면회 등 합성 안내로 제목/시간/장소/내용을 수정할 수 있다.
2. 외부 일정 ID와 버전을 넣고 가져온다. DB에 검토 대기로 저장되며 가족에게는 아직 보이지 않는다. 입력 일시는 기기 현지 시간, 표시 일시는 Europe/Helsinki다.
3. 간호사가 안내 내용과 필요한 공유 범위, 수신자를 검토한다. 진료·검사 내용에는 건강 정보 권한을 포함한다. 기본 예시는 건강 정보+돌봄 연락이며 초기 권한에서 Liisa에게만 발행 가능하다. 단순 연락 안내는 돌봄 연락 범위로 두 가족에게 발행 가능하다. 범위 선택은 실제 의료 분류/자동 AI 판단이 아니므로 검토가 필요하다.
4. 검토 체크 후 **검토 완료 · 가족에게 알림**을 누른다. 가족 화면의 가족확인사항에 안내와 미확인 건수가 표시된다. 현재 화면은 5초마다 재조회한다.
5. 가족이 **확인했어요**를 누르면 해당 가족의 확인 시각이 저장된다. 다른 가족의 확인 상태는 바뀌지 않는다. 간호사 화면에서 수신자별 확인 상태를 볼 수 있다. 확인은 내용 수신 확인이며 진료 완료·참석 약속·의료 동의를 뜻하지 않는다.
6. 추가 문의와 동행 여부 등은 같은 화면의 **가족확인사항 남기기**에서 작성한다. 기존 승인·발행 기반 답글, 기존 질문 이력은 유지된다.

## 변경·취소·권한

- 같은 외부 ID/버전/내용 재가져오기는 중복 안내를 생성하지 않는다. 같은 버전에 다른 내용을 넣거나 하위 버전을 보내면 거절한다.
- **일정 변경·취소 작성**은 상위 버전 입력을 채운다. 가져오기 후 기존 안내는 즉시 숨기고 재검토한다. 재발행하면 가족별 확인이 초기화된다. 취소도 별도로 검토·발행하여 취소 안내를 전달한다.
- **알림 회수**는 공개를 중단한다. 동의 변경 시 현재 동의 버전·모든 필요 범위가 일치해야 조회·확인이 가능하다. 권한을 다시 부여해도 이전 안내가 자동으로 살아나지 않는다. 회수 후 재검토·발행한다.
- 승인/권한 변경은 서버에서 검사한다. 저장 실패는 성공으로 표시하지 않으며 확인은 재시도해도 중복되지 않는다.

## 현재 연동 경계

`SIMULATED`, `TEAM_SYNTHETIC`, `emr_connected: false`. 합성 입력을 서버/SQLite에 실제 저장하고 수신자별 조회·확인을 처리한다. EMR 인증/조회/주기 동기화/FHIR 파싱, 실환자 매칭, 문자/이메일/푸시 발송은 구현·실행하지 않는다. UI 폼은 외부 시스템에서 들어온 정규화 일정의 검토를 시연한다.

- `POST /api/v1/staff/residents/{s}/family-events/import`: `{data_origin:"TEAM_SYNTHETIC", events:[{external_id,source_version,title,starts_at,location,details,status,required_scopes}]}`. 최대 50개, 전체 원자적 저장. `starts_at`은 시간대 포함 ISO8601, 상태는 scheduled/cancelled.
- `GET /api/v1/{staff|family}/residents/{s}/family-events`: 현재 접근 가능한 목록. 가족 응답에 다른 수신자 상태는 포함하지 않는다.
- `POST /api/v1/staff/family-events/{id}/publish`: `{recipients:[...],reviewed:true}`, If-Match와 Idempotency-Key 필요.
- `POST /api/v1/staff/family-events/{id}/withdraw`, `POST /api/v1/family/family-events/{id}/acknowledge`: 현재 버전의 If-Match와 Idempotency-Key 필요.

향후 실제 연동은 별도 승인된 비공개 환경에서 EMR 계약, 인증, 환자/가족 매핑, 공유 동의와 변경·취소 수신 방식을 정한 뒤 연결한다. 현재 공개 합성 PoC에 실환자 데이터를 넣지 않는다. 이 문서는 현재 구현 안내이며 후속 제품 명세 확정이 아니다.
