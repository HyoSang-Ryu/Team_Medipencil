# Stitch 디자인 적용 범위

기준: 사용자 제공 `stitch_medipencil_healthcare_platform.zip`의 9개 화면과 `serene_nordic_care/DESIGN.md` (2026-11-05). 화면의 가상 병원명·환자명·수치·의약품·예약 가능 좌석은 실제 데이터로 간주하지 않았다.

| 시안 | 적용한 화면과 동작 |
| --- | --- |
| 1 통계·리포트 | 직원 현황에서 원자료의 수면·수분·야외활동 추이, 가족 메시지 읽음 수를 표시. |
| 2 일일 차팅 | 직원이 식사·삼킴·측정값·투약/활동 관찰을 입력하고 서버에 **미발행 초안**으로 저장. 검토 단계로 옮겨 핀란드어 기록을 확인한 뒤 기존 보호자 선택·공유 절차 사용. |
| 3 가족 소통 | 직원의 공유 기록, 보호자 질문 답변, 면회 신청 확인, 보호자 메시지 처리. |
| 4 케어 일지 | 보호자에게 허용된 항목만 날짜별로 표시하고 식사·활동·수면·교류 필터 제공. |
| 5 가족·프로필 | 등록된 보호자와 공유 범위 표시, 화면 내 소식 분류 설정 저장. |
| 6 직원 모니터링 | 대상자별 최근 기록·대기 질문·면회 신청·공유 기록 수와 다음 업무 바로가기. 기록에 없는 실시간 바이탈은 만들지 않음. |
| 7 공지·메시지 | 승인된 직원 공유 기록의 읽음 확인과 반응, 보호자 질문/응원 메시지, 직원 처리 상태. |
| 8 면회 | 희망 방식·날짜·시간·인원 신청, 직원 확정/거절, 보호자 취소. 신청은 실제 시설 예약이 아님. |
| 9 보호자 홈 | 가족 사진/대상자, 마지막 기록 시점, 변화 카드, 일지·메시지·면회 바로가기. |

## 데이터와 권한

- 2026년 제공 시나리오 A/B와 각 대상자 대표 보호자 한 명씩을 유지한다. 보호자는 본인 대상자의 현재 공유 범위 안에서만 생활 기록·직원 메시지를 조회한다.
- 면회·응원 메시지·읽음·반응·알림 화면 설정은 `provided-workflow.sqlite`에 저장한다. 전자문자·푸시·실제 면회 예약은 실행하지 않는다.
- 차팅 초안은 직원만 읽고 수정한다. 가족 화면에는 선택 보호자에게 공유된 확인 기록만 나타난다. 수기 측정값은 합성 PoC 입력이며 기존 EMR이나 웨어러블 측정값으로 표시하지 않는다.
- 시안의 가족 초대는 대상자별 보호자 한 명이라는 현재 합의와 충돌하여 제공하지 않는다. 사진 첨부와 실제 예약 가능 시간, 실시간 병원 바이탈도 출처·전송/보관 기준이 없어 표시하지 않는다.

## 배포 순서

GitHub Pages는 성아 API를 사용하므로, 새 API가 올라가기 전에 새 화면이 공개되지 않도록 `[manual-release]` 커밋은 일반 push 배포를 보류한다. `deploy_api_only=true` 수동 실행은 성아의 **현재 웹 화면 파일을 검증된 기존 릴리스에서 그대로 가져와** API만 새 코드로 교체한 뒤 Pages 화면을 배포한다. 일반 push의 성아 자동 배포는 계속 꺼져 있다.
