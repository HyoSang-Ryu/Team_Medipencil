# 지원팀 PoC 검토 안내 — 로컬 검토 준비본

[English review guide](review-guide.en.md) · 화면 상단 **Interface / 화면 언어 → English**로 영어 안내·주요 화면을 사용할 수 있다. 질문·원문·근거는 번역하지 않으며, 발행 언어와 별개의 설정이다. 새로고침 후 영어를 다시 선택한다.

이 문서는 사용 순서와 의견 수집 양식이다. 새 상세명세나 지원팀의 실제 피드백이 아니다. 현재 배포 위치는 로컬이며 공유 접속주소는 없다.

## 실행 담당자

기존 Python/Node 설치는 [실행 안내](../development/runbook.md)를 따른다. 저장소 루트에서:

```bash
npm --prefix apps/web run build
.venv/bin/python tools/dev/run_demo.py --poc --port 8767
```

`http://127.0.0.1:8767`을 연다. `--poc`는 기존 Whisper/Ollama 설정 파일을 읽지 않고 둘 다 disabled로 시작한다. 직접 입력 모드에서는 AI 추론을 하지 않는다. 새 실행은 저장소 밖의 새 합성 DB와 run ID를 만들고 경로를 출력한다. 이를 회차 기록에 연결한다. 기존 DB를 자동 삭제하거나 초기화하지 않는다. 이전 회차 재개는 출력된 경로를 `--data-root /absolute/run-directory`로 지정한다. 서버 종료는 Ctrl+C다.

공유 배포 전까지 다른 컴퓨터에서 이 loopback 주소로 접속할 수 없다. 화면 공유는 설명용이며 지원팀이 직접 별도 세션으로 사용한 것과 구분한다.

## 검토 세션 준비

- 일반 브라우저/별도 프로필/다른 브라우저 중 서로 쿠키를 공유하지 않는 환경을 2개 이상 준비한다. 같은 프로필의 일반 탭 두 개 또는 같은 시크릿 프로필의 탭 두 개는 독립 세션이 아니다.
- 가족 A: **Liisa**. 직원: **Koskinen**. 권한 비교 가족 B: **Mikko**. 각 창에서 역할을 한 번 선택하고 자신의 창을 유지한다.
- 새로고침 후 역할 선택 화면이 나오면 동일 역할을 다시 선택한다. 기존 질문과 발행은 서버 DB에서 다시 조회된다.
- 데이터는 독립 합성자료만 입력한다. 실제 이름·연락처·환자 기록·실제 돌봄 음성·Veil 유래 자료를 넣지 않는다.
- 화면 상단의 한국어 PoC 안내를 펼친다. FI 버튼 대응을 함께 제공한다. 이 안내가 FI 전문가 검수 완료를 의미하지 않는다.

## 1차 설명과 2차 직접 사용 시나리오

| 순서 | 역할과 동작 | 관찰할 결과 |
|---|---|---|
| 1 | Liisa: “오늘 산책을 했나요?” 질문 입력 후 보내기 | 접수만 표시. AI 즉답 없음. 새로고침/동일 역할 재선택 후 유지 |
| 2 | 직원: 질문 큐에서 같은 질문 확인 | 다른 브라우저의 질문을 확인. 예정 지정 또는 미답변 유지 |
| 3 | 직원: 기록·발행 화면, 해당 질문 선택. 원문 “점심 후 직원과 산책할 계획이다.”, 유형 plan, 공개 분류 outdoors+health_context | 검토할 초안. 완료 문구를 추가하지 않음. 가족 창에는 초안 없음 |
| 4 | 직원: 원문을 실제로 확인한 합성 정정문으로 수정·저장, 검토 체크 후 승인 | 문구와 근거 연결 유지. 승인만으로 질문 answered/가족 공개 안 됨 |
| 5 | 직원: Liisa 대상 발행 미리보기 확인, 별도 검토·발행 | DB 발행 후에만 가족이 답과 근거를 읽음. plan은 그대로 계획 |
| 6 | Liisa: 답과 근거 열람, 새로고침 후 재조회 | 같은 내용과 근거가 유지. “진술/관찰/계획”을 검토자가 구분하는지 관찰 |
| 7 | Mikko: 같은 입주자 열람 | 건강정보가 섞인 위 문구·숨긴 근거가 응답과 화면에 없음 |
| 8 | 직원: 동의 후보 생성과 확인/철회를 별개로 시도 | 후보만으로 권한 변경 없음. 철회 뒤 이전 공개로 접근 불가 |

사용자가 막혔을 때 바로 대신 조작하지 말고 막힌 지점과 기대 결과를 먼저 기록한다. 같은 build/회차/시나리오를 사용해야 수정 전후 비교가 가능하다. 자동 시험의 승인 체크는 사용자가 내용을 이해했다고 판단한 증거가 아니다.

## 실제 의견 기록

지원팀의 실제 응답을 받았을 때만 FB-ID를 부여한다. 아직 등록된 의견은 0건이다. 아래 양식을 기존 팀 협업 도구나 회의 기록에 복사한다. 이 저장소에 개인 이름·연락처·비공개 의견 원문을 올리지 않는다.

```text
FB-ID: 실제 의견 수신 후 발급
회차 / build commit / 익명 역할 ID:
직접 사용 여부: 화면 공유 관찰 / 독립 세션 직접 사용
화면·동작 / 재현 순서:
예상 결과 / 실제 결과:
막힌 이유·영향 / 개선 제안:
질문~발행 시간 / 생성·사람 검토·수정 시간: 측정값 또는 미측정
공개 가능한 요약 / 비공개 원본 증빙의 내부 식별자:
조치: 필수 수정 / 개선 제안 / 확인 필요
수정 commit / 동일 사례 재시험 결과:
```

각 검토 후 질문한다: “질문은 누구에게 갔나요?”, “승인과 발행은 무엇이 다른가요?”, “산책은 예정인가요, 완료인가요?”, “Mikko에게 보이지 않는 이유를 이해했나요?”, “어디서 멈추거나 다시 확인했나요?” 답변은 실제 검토자가 한 말에 근거해 요약한다.

## PC-04 공유 검토를 열기 위한 미지정 사항

1. 팀이 승인한 테스트 서버·관리자·배포 가능 범위.
2. 검토자 접근 제한 방식과 HTTPS 또는 승인 VPN. 현재 데모 역할 선택을 인터넷에 그대로 노출하면 안 된다.
3. 가족/직원 계정 배정, 회차별 데이터 구분, reset 담당자·대상·권한.
4. 검토 일정·익명 역할 ID·기존 피드백 수집 채널·비공개 증빙 보관 위치.

이 항목이 없으므로 공유 배포와 실제 지원팀 사용 검증은 대기한다. 지원팀 의견 수집 후 `FB-ID → 문제 → 수정 → 동일 사례 재시험`을 기록하고, 그때 유지/변경/보류/제외 요구를 제안한다. 현재는 다음 상세명세를 확정하지 않는다. 대회 반입·재사용 허용은 별도 UNCONFIRMED다.
