# 로컬 음성 기록 및 차팅 — 2차 기능

2026-10-13 사용자 요청으로 직원 전용 `/staff/voice` 화면을 추가했다. GitHub push 및 성아 배포는 하지 않는다. 1차 핵심 과제인 가족 생활 현황의 범위를 변경하거나 후속 전체 명세를 확정하는 문서가 아니다.

## 사용 순서

1. 로컬 화면에서 직원 로그인 → **음성 기록**. 현재 대상은 독립 합성 입소자 Aino다.
2. 녹음 허가 참조와 합성자료 고지 확인을 입력한다. 음성 언어를 선택한다.
3. **녹음 중 실시간 전사**를 켜고 녹음한다. 6초 이후 0.6초 무음에서 분할하고, 12초에는 강제 분할하여 임시 전사를 누적 표시한다. 녹음 정지 → 마지막 구간 처리 → 다시 듣기 → **로컬에서 전사**로 전체 최종 전사를 저장한다. 별도 WAV 파일도 선택할 수 있다.
4. 이번 돌봄에서 확인할 항목을 선택하고 차팅을 시작한다. 기본 14개 항목을 표시하지만 해당 회차에 필요한 항목을 선택할 수 있다.
5. ① 일상생활(식사량/도움, 수분, 위생, 피부, 배설, 이동, 수면), ② 건강·바이탈/통증, ③ 복약/필요시 약, ④ 기분/사회적 활동을 보완한다.
6. 키워드 후보는 원문 그대로 표시하며 자동 확인하지 않는다. 내용 확인 / 알 수 없음 / 해당 없음 / 추가 확인 필요를 선택한다. 확인 내용에는 화자·기록 유형·관찰 시각을, 나머지 상태에는 사유를 입력한다.
7. 차팅 저장 → 원문 대조 확인 → 검토용 초안 만들기. 확인한 내용이 최소 한 항목 필요하다. 새로 로그인해도 저장된 차팅을 다시 열 수 있다. 저장하지 않은 입력은 복원되지 않는다.
8. **가족 안내 검토함**에서 기존 원문 검토·승인·동의·발행 과정을 따른다. 음성 차팅 완료는 승인이나 가족 공개가 아니다. 후속 확인 사유는 직원 차팅에 남고 확인된 사실로 바뀌지 않는다.

## 구현 경계

- 마이크는 사용자가 시작할 때만 요청한다. AudioWorklet로 모노 PCM16 WAV를 생성한다. 최대 180초/20 MiB 이내, 화면 숨김·화면 이동·로그아웃 시 트랙을 해제한다. 중지 뒤 브라우저 메모리에서 재생한다. 실시간 전사를 켜면 녹음 중 구간을 로컬 서버에 전송한다. 끄면 전사 버튼을 누르기 전에는 전송하지 않는다. 화면 이동 시 저장하지 않은 녹음은 보존하지 않는다.
- 로컬 모델은 기존 provider 설정을 사용한다. 이번 `--poc` 로컬 실행은 STT/LLM disabled다. 모델 다운로드·설치 및 실제 마이크 음성 전사 정확도 검증은 하지 않았다.
- 직접 합성 전사 입력은 STT 미실행이다. 차팅 후보 분류는 `charting-rules-v1`, `ai_executed=false`이며 LLM 기반 자동 구조화·진단·대화형 AI 비서가 아니다.
- 추가 음성으로 기존 차팅에 전사를 이어 붙이는 기능, 깨우기 단어, 토큰 단위 스트리밍, 다중 화자 분리, 실제 EMR 쓰기, 모델 학습은 미구현이다. 현재 보완 답변은 직접 입력한다.
- 날짜는 브라우저 현지시각 입력을 UTC로 저장한다. 자동으로 현재시각을 관찰시각으로 확정하지 않으며 ‘지금으로 입력’은 직원의 명시적 선택이다.
- 원문 전체의 scope와 health_context를 보수적으로 유지한다. 일반 생활 정보만 허용된 보호자에게 민감 원문을 낮은 권한으로 공개하지 않는다.
- 낙상/통증/복약 등 임상 업무용 판단 기준이 아니다. 항목별 필수성·번역·현장 편의성은 실무자 검토 전이다.

## 로컬 실행

Node 22를 PATH에 둔 뒤 저장소 루트에서:

```sh
VITE_MEDIPENCIL_DESIGN=xd npm --prefix apps/web run build
PYTHONPATH=apps/api/src .venv/bin/python tools/dev/run_demo.py --port 8780 --data-root /private/tmp/medipencil-voice-20261013
```

브라우저: `http://127.0.0.1:8780/staff/voice`. 같은 Mac에서 접속한다. 모바일 레이아웃은 390px 브라우저 화면으로 확인했으며 실제 휴대전화·마이크 기기 검증과는 다르다.

## 저장 및 API

추가 테이블 `voice_charts`는 capture와 선택 항목, 답변, revision, 최종 record 연결을 저장한다. 기존 source_events/record_versions/processing_jobs와 승인·발행 계약을 재사용한다.

- `GET/POST /api/v1/staff/residents/{subject}/voice-charts`
- `GET/PATCH /api/v1/staff/voice-charts/{chart_id}`
- `POST /api/v1/staff/voice-charts/{chart_id}/finish`

직원 권한·입소자 일치·TEAM_SYNTHETIC·유효한 원문·revision·idempotency를 검사한다. 완료 시 원문과 직원 보완 근거를 연결한 draft만 만든다. 이미 초안에 사용된 capture로 중복 완료할 수 없다.

## 로컬 모델 연결 정정 (2026-10-13)
초기 검증 명령의 `--poc`는 Settings 단계에서도 STT/LLM을 강제로 비활성화한다. 설치 부재가 아니었다. 이 Mac의 기존 Whisper medium.pt 및 Python 3.11 Whisper/Torch 런타임을 확인했고, 해당 옵션 없이 같은 로컬 DB/8780 포트로 재시작했다. 직원 providers API에서 whisper/medium.pt와 ollama/llama3.1:8b 설정을 확인했다. 실제 녹음 전사 및 LLM 호출 성공을 검증한 것은 아니다. `--poc`를 빼면 검토 안내/팀 코멘트용 PoC 모드도 꺼지지만 음성 기록 메뉴는 유지된다.

## 실시간 구간 전사 (2026-10-13 추가)

기존 `work/medipencil-standalone/src/main/webapp/WEB-INF/jsp/front/app.jsp`의 PCM 수집, RMS 무음 감지, 구간 전사 누적, 정지 후 마지막 구간 처리 완료를 기다리는 방식을 참조했다. 기존 30/45초 분할을 이 PoC의 3분 녹음에 맞춰 6/12초로 조정했다. 기존 외부 API 주소·인증·환자 자료를 복사하지 않는다.

- 설치된 Whisper medium을 별도 오프라인 worker에 한 번 로딩하고 구간 요청에 재사용한다. 16kHz PCM16 구간은 프로세스 메모리에서 처리하며 미리보기 음성/전사를 DB나 파일로 저장하지 않는다. 서버 종료·오류·취소 시 worker를 종료한다.
- 직원 권한, 합성자료, 녹음 허가와 현재 capture 상태를 처리 전·후에 다시 검사한다. 동시에 실행되는 로컬 AI 작업은 기존 실행 잠금으로 제한한다. 허가 철회 후 결과를 반환하지 않는다.
- 구간은 순서대로 요청한다. 실패 시 미리보기를 중단하고 전체 녹음 전사로 복구하도록 안내한다. 화면 이탈·사용자 전환 뒤 늦은 결과는 반영하지 않는다. 미리보기는 차팅 근거로 승격하지 않는다.
- 정상 경로도 전체 최종 전사 버튼을 눌러 기존 영속 STT job과 근거 저장·정리 계약을 거친다. 원래 메디펜슬의 구간 텍스트 직접 차팅과 다른 보수적인 연결이다.
- 화면의 **합성 음성 시험용 녹음 허가 생성**은 합성자료 고지 체크 후 직원의 명시적 클릭으로 시험 허가 근거를 저장한다. 실제 입소자 동의의 대체물이 아니다.
- 재현: `PYTHONPATH=apps/api/src .venv/bin/python tools/dev/verify_live_stt.py`. Mac의 설치된 `say` 핀란드어 음성과 ffmpeg로 만든 독립 합성 TTS를 실제 endpoint/Whisper에 보낸다.
- 실제 API 시험: 3.67초 음성, 최초 7.26초 / 재사용 2.45초. `Tämä`가 `sama`로 잘못 전사됐고 `Ulkoilu ei toteutunut.` 부정 문장은 유지됐다. 두 구간 시험이며 정확도·임상 성능·일반적인 속도를 보장하지 않는다. 물리 마이크, 장시간 녹음, 실제 휴대전화와 핀란드어 전문가 검수는 미완료다.
- `POST /api/v1/staff/captures/{capture}/live-transcript?language=fi&sequence=0`는 `provisional=true`, `saved=false`와 실제 실행 메타데이터를 반환한다. 모델 다운로드, 클라우드 STT 및 실제 EMR 전송은 없다.
